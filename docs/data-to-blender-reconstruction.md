# Public geography to Blender: Melbourne City Loop

Research checked 20 September 2026. This is a source and workflow plan only; it does not change the playable alignment, scenery or assets. Coordinates are geographic source coordinates until explicitly transformed into the simulator's local frame. The game origin is longitude 144.9671, latitude -37.8183; X east, Y up, Z south. Government transport and footprint geometry constrains horizontal relationships, not the operational track alignment or absolute rail elevation.

“Open” here means a public dataset page and listed downloadable/API resources, not that every large archive or service was fetched and tested. Source catalogue dates and pixel spacing are not a promise of current condition or of precise station construction dimensions. The photomesh's photographic pixels, third-party reference photos, generated materials, and locally authored assets each retain their own provenance; a government CC BY credit does not cover all visible content.

## Route-wide reconstruction priorities and Southern Cross pilot

Start with the low aerial context cut already documented for Southern Cross: local X `[-1800, -1050]`, Z `[-450, 260]`, below game Y=40 m. Those photographic sheets were removed because they sit above the approximate rail datum; this box is a targeting window, not a claim that every building in it is missing. Keep the documented station-conflict exclusions and playable rail untouched.

### Validated 2014 Southern Cross sample

The City API accepts a spatial filter. The bounded request was:

```text
GET https://data.melbourne.vic.gov.au/api/explore/v2.1/catalog/datasets/building-outlines-20140/records
  ?where=within_distance(geo_point_2d, GEOM'POINT(144.9525 -37.8184)', 300m)
  &limit=100
  &select=geo_point_2d,geo_shape,fmtaddress,mccid_int,mccid_str,height,zmin,zmax,floors,build_year,easting,northing
```

The response reported 56 records. Fields observed were `geo_point_2d`, `geo_shape`, `fmtaddress`, `mccid_int`, `mccid_str`, `height`, `zmin`, `zmax`, `floors`, `build_year`, `easting` and `northing`. Four components named “Southern Cross Station 85-161 Spencer Street” share `mccid_int=108973`; their model heights are 19.13–39.09 m and reported floors are 3. The component at `(144.9516194, -37.8187107)` has `height=19.13`, `zmin=6.58`, `zmax=25.71`. Its projected **bounding box** overlaps the existing 2023 object `3298` at 0.85 IoU and object `3299` at 0.82; this is bounding-box overlap, not polygon IoU. Object `3298` belongs to structure `812676` and records a 2023 section from 22.3 to 29.0 m with `footprint_extrusion=6.7` and `roof_type=Flat`. The two datasets therefore describe overlapping parts of the same station context with different sectioning and height semantics; the 2014 record is useful as an address/floor/height cross-check, not a proven roof replacement. Its `zmin` also differs, so do not merge its elevations into the game datum without resolving the vertical reference. The 2014 catalogue explicitly says roof projection is used only where no enclosing walls exist.

The API sample confirms a compact lookup route for adding building identities and approximate floor/model-height annotations to the whole corridor's existing 2023 sections. It does not justify replacing their footprints or generating a supposedly surveyed station roof.

### Apply the source evidence along the route

Use each source only for the geography it actually contains:

- **Flinders Street–Southern Cross viaduct and Yarra banks:** the project already has clipped Vicmap road/rail/water/open-space features, mapped trees and selected 2020 textured-mesh patches. The 2018 DSM index identifies six tiles intersecting the documented corridor bounds, but their large TIFF members are not a low-cost add-on. Prioritize Blender-authored viaduct spans, river-edge transitions and a few source-matched surrounding building shells using existing footprints and photomesh references.
- **Southern Cross approach, hall exterior and north portal:** the 2023 building sections plus verified 2014 address/floor metadata can identify and size surrounding masses; use selected 2020 mesh nodes for visual reference. Station/hall and portal detail still needs authored geometry and appropriate visual references. The public city surface datasets do not encode operational station circulation, platform edges or the playable track alignment.
- **Underground approaches and the other loop stations:** the City surface datasets describe above-ground context only. Vicmap rail linework supplies network topology, not underground room shapes, platform plans, track count, vertical alignment, clearances or accurate station interiors. Preserve the training route as authored and source station interiors separately from verified station maps/photos; do not present surface terrain or footprints as a reconstruction of underground works.

For a first Blender pilot, select one non-conflict retained 2023 building section beside the Southern Cross hall, enrich its ID with the corresponding 2014 `fmtaddress`/floors/model-height row, then model only one clean podium/tower/roof envelope. Keep government polygons as a hidden reference collection and keep authored facade texture separate. If the design needs roof detail, trace visible form from a matched 2020 mesh tile or photograph; the 2014 record alone is insufficient. Store source IDs, API query, coordinate system and attribution on Blender objects and the asset manifest.

The first acceptance target should be one large, retained building silhouette beside the Southern Cross hall in the player's cab-visible approach: keep its geographic footprint fixed; add a readable podium break, tower setback and roof termination; use a small set of reusable authored facade materials. Source sections supply envelope and height only, not window rhythm or cladding. Keep object IDs and attribution in Blender custom properties and the exported asset manifest.

The reproducible data preparation should be narrowly scoped to a spatial query (or local bbox) and emit an intermediate JSON/GeoJSON with source URL, query, retrieval date, licence, 2014 mccid/address fields, matched 2023 structure/section IDs, original coordinate systems, source rings and vertical fields. Transform to the game frame only in a separate Blender import step. The project already has `scripts/prepare-city.mjs` for 2023-derived game geometry and `scripts/blender/build_viaduct.py` as the pattern for deterministic Blender-authored, named, compact exports. A future `scripts/prepare-cityloop-reference.py` should fail if requested source records are absent, report ambiguous spatial joins, and never rewrite `buildings.json`, station-clearance data or the training route.

Do not bundle the 2014 sample unless its IDs and annotations are used by an authored asset or an explicit building-identity index. Do not download the point cloud archive while its official link is 404. Although byte ranges make it possible to extract one DSM ZIP member, the Southern Cross tile alone is roughly 312 MB compressed; defer it until the visual question justifies that transfer. The 2020 photomesh's published I3S nodes and existing 2023 footprints remain the strongest immediately usable source geometry for surface scenery. Neither is an underground station plan.
